# Observation-Led Ad Compiler

## Rule
The master contract is evidence, not the final model prompt. Never discard it. Compile it.

## Sequence
Observe → distinguish inference → lock identity/product/topology → choose operation → choose one narrative argument → select at most five visible actions → one camera family → one emphasis event → final state → critical negatives → platform/workflow adapter → render → deterministic text/composite → QA → ledger.

## Operation semantics
- generate: no source media required.
- prompt: compile only; no inference call.
- motion_spec: create/validate contract and timeline only.
- edit: localized source change; preserve all unmasked content.
- transform: broad intentional style/material/world change while retaining declared locks.
- variation: same contract and composition family; controlled seed/parameter differences.
- extend: continue a source image/video spatially or temporally; preserve boundary continuity.

## Distillation budget
Final prompt order: task; locks; subject/product action; environmental action; camera; one event; final state; 3–6 style tokens; 10–18 negatives. Remove confidence scores, rationale, duplicated adjectives, typography timing, QA prose, and unsupported effects. Typography and exact CTA timing are post-production concerns.

## Ad concept requirements
Every variant must have a distinct audience motivation, argument, proof mechanism, first frame, and click reason. A crop, hue shift, or rewritten headline is not a concept variant.

## Model asset governance
No checkpoint or LoRA enters production without version ID, hash, base-model compatibility, trigger words, weight range, license review, and a recorded test render. Do not combine incompatible base families. Begin LoRA weights conservatively (commonly 0.5–0.8) and alter one model variable per test.
